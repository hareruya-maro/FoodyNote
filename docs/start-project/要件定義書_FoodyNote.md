# **アプリケーション要件定義書**

## **プロジェクト名：Foody Note (フーディノート)**

旧仮称: 食事と不調の相関チェッカー  
作成日: 2026年1月15日  
バージョン: 2.0 (正式名称決定版)

## **1\. アプリ概要**

### **1.1 コンセプト**

「私のお腹、何に弱いんだろう？」を可視化するアプリ。  
ユーザーが食べた物の「写真」と、その後の「体調変化」を記録することで、\*\*「不調が起きる前に共通して食べていた食材」\*\*をランキング形式で提示する。診断は行わず、ユーザー自身や医師が原因を特定するための「客観的なデータ」を提供するサポートツール。

### **1.2 ターゲットユーザー**

* 原因不明の腹痛、下痢、膨満感に悩む人（IBS傾向の人など）。  
* 食後に眠気やだるさを感じやすい人。  
* 病院に行くほどではないが、なんとなく特定の食べ物が合わない気がしている人。  
* 医師に「いつ、どんな時に症状が出ますか？」と聞かれてうまく答えられない人。

### **1.3 提供価値 (Core Value)**

1. **記録の手間を最小化:** 写真を撮るだけでAIが材料を自動タグ付け。  
2. **気づきの提供:** 「そういえば、調子が悪い時はいつも〇〇を食べていた」という隠れたパターンの発見。  
3. **医師への説明補助:** 診察時に見せるだけで伝わる「医師提示モード」の搭載。

## **2\. 機能要件 (Functional Requirements)**

### **2.1 食事記録機能 (Meal Logging)**

* **写真撮影・アップロード:** スマホのカメラ起動またはライブラリから画像を選択。  
* **AI材料解析:** 画像から料理名と構成食材（タグ）を自動推定する。  
  * *要件:* 料理名だけでなく、アレルゲンとなりやすい材料（小麦、乳、卵、特定原材料など）や成分（カフェイン、脂質など）をタグ化する。  
* **タグ編集:** ユーザーによるタグの追加・削除機能（AIの誤検知修正用）。  
* **日時記録:** 撮影日時または登録日時を保存。

### **2.2 体調記録機能 (Symptom Logging)**

* **ワンタップ記録:** 「お腹痛い」「だるい」「頭痛」などのプリセットボタンで素早く記録。  
* **重症度記録:** 3段階（軽・中・重）などで記録可能にする（オプション）。  
* **メモ欄:** 自由記述で詳細を残せるエリア。

### 2.3 エージェント分析機能 (Agentic Insight) - NEW!

多角的考察レポート: ボタン1つで以下のエージェントが協調してレポートを生成する。

* **Analyst Agent:** ユーザーのログから統計的相関（Aを食べるとBが起きる）を発見。
* **Researcher Agent:** その相関に対し、栄養学・医学的知識（FODMAP、消化速度など）を検索・照合し、裏付けを行う。
* **Writer Agent:** ユーザーに分かりやすい言葉で「仮説」と「次回の対策」を執筆。

出力例: 「カフェラテで腹痛が起きていますが、ヨーグルトでは起きていません。乳アレルギーではなく『乳糖不耐症』の可能性があります。次回は無乳糖ミルクを試すか、酵素サプリの利用を検討してください。」

### 2.4 AI能動問診機能 (Active Inquiry) - NEW!

自律的な質問生成: AIが画像解析時に「分析に必要な情報が足りない」と判断した場合（例：カレーのルーに小麦が含まれるか不明、カフェラテのミルクの種類など）、自動的に質問を生成する。

選択式UI: ユーザーはチャット入力不要。AIが提示する 2〜4択のボタン をタップするだけで回答完了。

例：「このカレーは市販のルーを使っていますか？」→ [はい (小麦あり)] [いいえ (スパイスのみ)] [不明]

### **2.5 設定・その他**

* **医師提示モード:** 診察室で提示するための閲覧専用画面。  
* **アカウント管理:** Firebase Authを利用したログイン（Web/アプリ間のデータ共有用）。

## **3\. 画面構成案 (UI/UX)**

**Universal Design:** React Native for Web (Expo) により、モバイルブラウザとネイティブアプリで共通のUIを提供する。

| 画面名 | 概要 |
| :---- | :---- |
| **ホーム (Dashboard)** | 今日の記録タイムライン。「食事を記録」「不調を記録」の2大FAB（フローティングアクションボタン）を配置。 |
| **食事記録画面** | ファイル選択/カメラ起動 → AI解析結果確認画面（タグ修正） → 保存。 |
| **体調記録画面** | 症状アイコン選択 → 保存。 |
| **分析レポート画面** | 「あなたの不調トリガー候補」ランキング表示。期間指定フィルター。 |
| **履歴/カレンダー** | 過去の記録を振り返る画面。 |
| **医師提示モード** | 診察室用のフルスクリーン閲覧モード。 |

## **4\. システムアーキテクチャ・技術選定案**

戦略: React Native for Web (Expo) を採用。単一のコードベースで、まずはハッカソン用にWeb版を提供し、その後スムーズにiOS/Androidアプリとしてリリースする。  
構成: Monorepo構成（Turborepo）を採用し、将来的な拡張性を担保する。

### **4.1 フロントエンド (Universal App)**

* **Framework:** **Expo (React Native for Web)**  
* **UI Library:** NativeWind (Tailwind CSS)  
* **Routing:** Expo Router

### **4.2 バックエンド (BaaS)**

* **Platform:** Firebase (Auth, Firestore, Storage, Hosting)

### **4.3 AI / API**

* **Image Analysis:** Google Gemini API (Gemini 3 Pro / Flash)  
  * 食材タグの自動生成に使用。

## **6\. 開発ロードマップ**

### **Phase 1: ハッカソン向けWebアプリ開発 (MVP)**

* **開発:** Expoを用いてWeb向けに開発。  
* **デプロイ:** Firebase Hosting等へWeb版を公開。  
* **検証:** URL共有によるフィードバック収集。

### **Phase 2: AI精度向上と機能拡充**

* 分析ロジックの改善。  
* カレンダービューの実装。

### **Phase 3: ネイティブアプリ化（iOS/Android）**

* **ビルド:** EAS Buildを用いて、既存コードベースからiOS/Androidアプリを生成。  
* **リリース:** App Store / Google Playへの申請。
